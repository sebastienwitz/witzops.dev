# Architecture

Technical architecture of witzops.dev.

## Overview

The site is a **static HTML site** generated by Astro 6 at build time
and served from Cloudflare Pages. There is no server-side rendering, no
API layer, and no runtime database. All content is committed to the
repository as Markdown or Astro components.

## Build pipeline

```
Source (src/) → Astro build → Static HTML/CSS → Cloudflare Pages → CDN
```

### Local development

```sh
npm run dev       # Astro dev server with HMR at localhost:4321
```

### Production build

```sh
npm run build     # Outputs static files to ./dist/
npm run preview   # Serves ./dist/ locally for verification
```

### CI

GitHub Actions runs `npm ci && npm run build` on every push and PR to
`main`. The workflow does not deploy — deployment is handled by
Cloudflare Pages' git integration.

## Component tree

```
BaseLayout.astro
├── Header.astro
│   └── Navigation items (from src/data/site.ts)
├── <slot />  (page content)
│   ├── index.astro
│   │   ├── Callout.astro
│   │   ├── ProjectCard.astro
│   │   └── TagList.astro
│   ├── projects.astro (project listing)
│   ├── architecture.astro (ADR listing)
│   ├── blog.astro (article listing)
│   │   └── ArticleCard.astro
│   ├── lab-stack.astro (stack inventory)
│   └── about.astro (about page)
└── Footer.astro
```

## Data flow

```
src/data/site.ts
  ├── siteTitle         → BaseLayout, Header, Footer
  ├── siteTagline       → BaseLayout, Header
  ├── navigationItems   → Header
  └── socialNote        → Footer
```

Site metadata is centralized in `src/data/site.ts`. Components
import only what they need.

## CSS architecture

- **Global styles** (`BaseLayout.astro`, `<style is:global>`):
  CSS custom properties, reset, typography, grid utilities, and
  responsive breakpoints.
- **Component styles** (each `.astro` file, scoped `<style>`):
  Component-specific styles, scoped by Astro's build process.

## Routing

Standard Astro file-based routing:

```
src/pages/index.astro        → /
src/pages/about.astro        → /about
src/pages/projects.astro     → /projects
src/pages/architecture.astro → /architecture
src/pages/blog.astro         → /blog
src/pages/lab-stack.astro    → /lab-stack
src/pages/404.astro          → 404 page
```

## Decisions and resolutions

- **Static output only**: No SSR, no API routes. Simplifies deployment
  and removes an entire class of runtime concerns.
- **Astro over Next.js/Gatsby/Hugo**: Lightweight, component-based but
  zero JS by default, excellent Markdown support. See
  [docs/decisions/0001-use-astro.md](decisions/0001-use-astro.md).
- **Cloudflare Pages over Vercel/Netlify**: Matches the Cloudflare
  ecosystem already used for DNS. See
  [docs/decisions/0002-use-cloudflare-pages.md](decisions/0002-use-cloudflare-pages.md).
- **Separate public and private docs**: Operational details stay
  private. See
  [docs/decisions/0003-separate-public-and-private-docs.md](decisions/0003-separate-public-and-private-docs.md).
